# m0n0: локальная подготовка к публикации

Проверено 27.10.2026. Ничего не опубликовано. Внешние аккаунты не изменялись.

Исходники сайта находятся непосредственно в `dist/`: HTML, CSS и обычный JavaScript.
Нет npm-зависимостей, серверной части, базы, API, переменных окружения сайта или сборщика.
Python нужен только для локальной проверки/упаковки, Node.js — для проверки синтаксиса JS.
`vectorize.py` — вспомогательный генератор контуров букв, не часть production-сборки.
Не запускайте его для публикации: он требует fontTools и локальный шрифт Windows.

## Сборка и обновление

Из каталога `studio` выполните `python scripts/build.py`.
Проверяются ссылки HTML на локальные файлы, переносимость путей, синтаксис всех JS,
разрешенные типы файлов и несколько распространенных сигнатур секретов.
Это базовая проверка, не исчерпывающий аудит секретов или браузерный тест.
Готовый ZIP появляется в `release/`, имя содержит хеш содержимого.
Для хостинга нужны только файлы внутри ZIP / `dist`, без внешнего каталога `dist`.
`.git`, `.openai`, скрипты, архив исходников и документацию на веб-сервер не загружать.
Каталог `release` игнорируется Git. `dist` хранится в Git, поскольку это исходный код.

Маршрутизация одностраничная через якоря `#home`, `#about`, `#work`.
Перезапись всех URL на index.html не нужна. CSS/JS используют относительные пути.
Шрифты системные; рисунки и эффекты сделаны CSS/SVG/JS, внешних CDN нет.
Форма только скачивает бриф, отправка заявки не подключена.

В портфолио пять проектов: +product, Яки Суприм, ЕМК, horyy и ЖК Характер.
URL задаются в `dist/projects.js`. Короткое нажатие открывает сайт в новой вкладке,
перетаскивание листает галерею; клавиша Enter открывает выбранную карточку.
В обоих режимах показаны реальные записанные взаимодействия из первых экранов.

Видео и постеры: `dist/assets/projects/`; параметры файлов: `manifest.json`.
Сцены записаны через интерфейс браузера с локальных сайтов. Исходные записи находятся
в игнорируемом `release/portfolio-capture/`, кодирование — `scripts/encode_portfolio_loops.py`.
Список проектов и записанных действий: `artwork/portfolio-recordings.json`.
Видео подгружаются при приближении к портфолио; невидимые превью ставятся на паузу.
При prefers-reduced-motion остаются статичные постеры. Парящие и падающие арт-карточки
не изменяются этим обновлением.

## Git и автоматизация

В этом каталоге уже есть Git, ветка `main`, последний исходный коммит `c9c680f`.
Remote отсутствует. Не добавляйте весь родительский каталог: в нем отдельный пустой Git.
Изменения подготовки оставлены для просмотра без коммита и push.

После подтверждения создать ПРИВАТНЫЙ репозиторий студии на выбранном Git-сервисе,
добавить его SSH URL как origin и отправить проверенные изменения.
Не вставлять токены в URL или файлы. Перед публичным переносом проверить также историю Git.

Для Beget/SpaceWeb Git сам по себе не загружает файлы. Предлагаемая схема:
push main → CI → `python scripts/build.py` → `python scripts/deploy_ftps.py`.
CI-провайдер и поддержка FTPS конкретного аккаунта пока не подтверждены, workflow не активирован.
Скрипт FTPS подготовлен локально, не запускался и не протестирован с хостингом.
В CI Secrets сохранить FTPS_HOST, FTPS_USER, FTPS_PASSWORD; в переменных задать
FTPS_DIRECTORY (точный абсолютный document root выделенного сайта), при необходимости FTPS_PORT.
DEPLOY_APPROVED=yes разрешать только после вашего подтверждения первой публикации.
Использовать отдельный FTP-аккаунт с доступом только к сайту и подтвержденный серверный TLS.
Обычный незашифрованный FTP не использовать; при отсутствии FTPS выбрать другой
подтвержденный защищенный способ. Скрипт не удаляет серверные файлы и загружает index.html последним;
загрузка не атомарна. Перед первым обновлением сохранить копию удаленного сайта.
Квоты/стоимость CI выбранного Git-сервиса проверить до включения.

Для каждого реального статического демо на SourceCraft после вашего согласия нужны
отдельные публичный репозиторий и публичная организация. В основной ветке создать
`.sourcecraft/sites.yaml` со следующим содержимым (если готовые файлы в dist):

```yaml
site:
  root: dist
  ref: main
```

Это инструкция для будущих проектов, не конфигурация студии: она не включает случайную публикацию.
Если демо требует сборки, сначала определить его стек и настроить CI либо отдельную
ветку готовой сборки. Sites обслуживает файлы, не запускает backend или npm автоматически.
После активации Sites push в выбранную ветку автоматически обновляет сайт за несколько минут.
Предпочтительно push сразу в SourceCraft, без зеркала с дополнительной задержкой.

## Подключение домена и перенос

Добавить собственный домен в панель хостинга и привязать к каталогу сайта.
У регистратора задать DNS-серверы из панели либо A/AAAA/CNAME именно с предоставленными
значениями. Не выдумывать IP; не добавлять AAAA без поддержки IPv6; сохранить MX/TXT почты.
Дождаться DNS, выпустить сертификат для домена и www, проверить HTTPS, затем включить
HTTP→HTTPS и выбрать канонический адрес. На бесплатном Beget сначала подтвердить возможность
SSL на собственном домене: общая реклама SSL на платном хостинге этого не доказывает.
На техническом поддомене Beget HTTPS не считать доступным.

Перенос: повторить проверку, загрузить содержимое dist на любой статический хостинг,
подключить TLS, проверить сайт до переключения DNS, сменить DNS и URL в projects.js.
Для студии нет привязки к runtime провайдера. Серверные демо потребуют отдельной оценки.
Старые файлы и публикации не удалять без согласования.
